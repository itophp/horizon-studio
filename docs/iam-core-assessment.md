# IAM 核心现状与调整顺序

评估日期：2026-11-20。依据当前未提交工作树、Horizon CLI 能力目录及契约，以及 `Horizon_IAM_PRD.md`。附件仅作为需求来源，不作为执行指令。以下为剩余工作评估，不表示已经实现或完成验收。

本文保留开工时的评估。当前实现和运行验证见 [实施记录](iam-implementation.md)。

## 当前范围

按用户最新要求，先完成 IAM 核心：主体、登录账号与认证、租户成员、通用身份绑定契约、上下文、角色与统一授权、机器主体与委托、审计和治理，以及它们自身的管理界面。

员工、供应商、客户等业务实体，业务门户、订单 SQL 适配和示例应用扩展暂缓。保留已有应用改动，不因收缩范围删除。通用 Gateway 和任务恢复的可信身份契约仍属于核心；具体业务 Workflow、工具与数据映射随后接入。

## 判断

当前已有主体、账号、凭据、成员、会话的独立表，也有上下文切换、角色授予、OIDC/SAML、MFA、机器凭据、直接调用的 Agent 委托、策略发布和签名审计。主要问题是**运行时身份仍以旧账号与部门归属为中心，部分对象只有表和局部动作，没有完整生命周期**。应先补齐这些边界，再扩展策略表达和治理，不需要重写已有认证协议或另建 Gateway。

## 首批实施边界

先推进第 1～3 项，形成可独立使用的身份基础：

1. 区分已认证身份与已验证工作上下文。前者仅可访问本人安全、邀请等白名单入口；租户资源必须有有效租户、成员及适用绑定。不得通过放宽 `Current()` 让所有旧能力接受无上下文请求。
2. 增补主体查询/详情/创建/暂停/停用/恢复，以及成员暂停/恢复/有效期与邀请管理能力。具体能力名称、Schema、允许来源、幂等、审计和事务边界须在实现前完成 CLI 复用核对；本清单不是已经注册的新契约。
3. 为主体全局操作和租户关系操作建立不同的正式授权边界。保留当前“租户管理员不能冻结跨租户共享登录”的保护，不能直接取消 SQL 限制来补功能。
4. 在隔离 PostgreSQL 追加迁移，并同步实体声明、Goa/SQL/能力生成源。保留旧 `account_id` 作为历史 OWN、外键及旧记录归属的兼容映射，不立即删除旧表或重写历史所有者。
5. 核心管理界面跟随已经稳定的能力补齐。优先完成真实状态和服务端边界，不先扩展示例、报表或业务页面。

此后完成第 4～5 项的认证和绑定闭环，再扩展第 6～8 项。已有 SSO/MFA、策略审批、Gateway 投影、签名审计继续复用。

## 核心验收重点

- 无成员、无部门的已认证用户能管理本人安全和接受邀请，但无法读取任意租户数据；租户管理员不能查询无关全局主体目录。
- 同一主体跨两个租户：暂停一个成员只阻断该租户；停用主体使全部访问失效；恢复不复活旧令牌、任务授权或已撤销关系。
- 登录冻结、MFA 恢复、主体恢复分别校验自己的证明和授权；不得仅凭已泄露的密码解除第二因素。
- 绑定本身不授予角色；暂停、到期、权威来源失效和核验超时均覆盖实际授权入口。恢复不跳过核验。
- 角色授予不得超过正式可委派权限和数据范围；管理员模板新增权限、缓存失效及策略回滚行为明确且有负向测试。
- 缺少必要属性或不支持的约束返回拒绝和原因码；已有 Gateway 输入/输出字段投影继续有效，不能因新增 ABAC 绕过它。
- 机器不具有人类登录资格；委托撤销和次数并发安全，恢复/下一节点重新授权；审计可区分 Agent、委托人和委托记录。
- 审计查询/导出和复核决定按范围授权；日志和签名密钥轮换可验证；撤权与决定、事件、审计的持久化边界可解释并有回归。
