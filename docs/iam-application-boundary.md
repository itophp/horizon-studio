# IAM 与应用边界

## 责任划分

业务应用拥有登录页、登录入口、企业、部门和账号管理页面及其业务生命周期。应用入口使用部署声明的应用 ID 解析受信任的凭据命名空间，再把用户名、密码和 MFA 数据交给 IAM。应用不能自行判断租户、角色或数据范围。

IAM 提供主体、登录凭据、租户成员、登录身份、会话、授权决策、资源目录、审计、MFA 和恢复证明。登录后所有业务应用仍通过 Capability Gateway 使用 IAM 的 Principal 和授权结果。

## 应用登录命名空间

用户名在应用命名空间内唯一。部署注册中的 signIn.id 和 signIn.namespace 确定应用入口，命名入口为 /sign-in/<id>。默认管理应用使用 administration，前端不再要求用户填写认证域。应用命名空间来自服务端部署注册，客户端不能通过请求字段覆盖。

注册和密码找回复用应用登录入口。应用路由固定命名空间后，IAM 只按该命名空间查找登录账号。OIDC/SAML 入口和回调目前归默认管理应用使用，完成后的会话和授权由 IAM 管理。

企业、部门和账号 Runtime 页面由托管的 com.horizon.identity 应用贡献。IAM 继续维护这些对象作为租户成员、作用域和授权所需的最小引用，页面和能力入口归应用。

## 约束

- 不接受客户端提交的 realm 作为认证边界。
- 应用登录 ID、命名空间和默认入口由部署清单校验唯一性。
- 不同应用允许同名账号。密码、注册证明和重置证明均按所属应用校验。
- 认证和凭据生命周期沿用 IAM 现有审计事件。
- 登录成功后应用只读取 IAM 返回的会话和授权上下文，不复制权限或审计实现。
